### Comprehensive 8-Week Journey Overview

Reflecting on the 8-week internship program with the AWS - First Cloud AI Journey (FCJ) (from 15/06/2026 to 14/08/2026), this experience stands as a significant milestone in my professional development. Moving beyond theoretical knowledge, this program provided a hands-on environment where I independently architected, built, and deployed the Awsplace project—a fully functional cloud-based application.

This journey marks a substantial transition from theoretical cloud knowledge to practical cloud engineering. I gained practical experience in architecting systems for high availability, ensuring robust security, and optimizing operational costs. Furthermore, the rigorous nature of the program and strict weekly deadlines have significantly enhanced my discipline, focus, and ability to thrive in a professional, agile work environment.

### Technical Skill Stack Acquired

The FCJ program helped me build a robust and highly demanded technology stack:
- **Compute & Storage:** Confidently provisioning and managing EC2 instances (Linux/Windows). Efficiently managing static assets with Amazon S3 and configuring block storage with EBS.
- **Database Management:** Deploying and managing relational databases with Amazon RDS (MySQL/PostgreSQL), understanding backup retention and Multi-AZ deployments.
- **Networking & Content Delivery:** Utilizing Route 53 for domain management and configuring CloudFront as a global CDN to accelerate content delivery.
- **Version Control & DevOps:** Proficient in using Git and GitHub for source code management, branching strategies, and secure merges.

---

### Key Challenges Overcome

1. **Custom Domain & SSL Configuration:** Initially faced significant hurdles with SSL Certificate Validation and pointing DNS records (CNAME/ALIAS) to AWS CloudFront. By methodically researching DNS propagation and Route 53 mechanics, I successfully resolved the issues, achieving a stable, HTTPS-secured application.
2. **IAM Permission Denied Errors:** Encountered system access errors (e.g., an EC2 instance failing to read from S3). Instead of granting broad Admin access, I utilized CloudTrail logs and IAM policy simulators to grant the exact, least-privilege permissions required.
